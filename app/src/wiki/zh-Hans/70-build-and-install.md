## 构建 {#building}

在[构建](app:build)上按**构建**（{key:build}）。Audiodiver 会为游戏转换新音频，并修补存放或播放被替换声音的音频库（[是哪些](#every-bank-with-the-sounds)）。然后它会检查结果，并打包成一个以模组名称和版本命名的 ZIP。

构建不会更改项目、音频文件或游戏。

如果项目有问题，例如缺少文件，或者名称无法被模组管理器使用，“构建”按钮会不可用。选项卡会在按钮上方列出这些问题。

### 目标文件夹 {#destination-folder}

ZIP 会放入项目文件旁边的 `build` 文件夹。要构建到其他文件夹，请按**目标文件夹**下的**更改**。**恢复默认**会改回 `build` 文件夹。构建只会添加 ZIP，以及开启后的[补丁文件](#patch-files)，因此多个模组可以共用一个文件夹。Audiodiver 不会构建到游戏文件夹中。

## 模组管理器显示的内容 {#what-the-mod-manager-shows}

[项目](app:project)选项卡会预览模组管理器显示的图标、名称和描述。

### 名称和描述 {#name-and-description}

名称中只使用字母、数字和空格，并且不要包含版本号。模组管理器会保留首次导入时的名称，因此请在分享模组之前确定名称。描述是可选的，会与模组一起显示。

### 版本 {#version}

**下一个版本**是下一个 ZIP 名称中的编号。每次构建后它会加一，除非关闭了**每次构建后提升版本号**。

### 图标 {#icon}

在您选择图片之前，图标是 Audiodiver 的默认图标。图片会以中心为准裁剪成正方形，并缩放为 540 × 540，即模组管理器使用的尺寸。您也可以把图片拖放到预览上。**边框**、**边框颜色**和**圆角**可为图标（无论是默认的还是选择的）加上外框。

### 模组 ID {#mod-id}

模组管理器通过模组 ID 识别模组。只要 ID 不变，新的构建就会更新已安装的模组。当您复制一个项目来制作另一个模组时，请按**生成新 ID**，这样副本会作为独立的模组安装。

要让构建更新您以前制作的某个模组，请按**更改**并粘贴该模组的 ID，即模组 `manifest.json` 中的 `Guid`。撤销可恢复旧 ID。

## 构建选项 {#build-options}

这些设置位于构建选项卡上的**构建选项**下。

- **每次构建后提升版本号**会让每次构建都有新的 ZIP 名称，之前的 ZIP 会保留。关闭时，下一次构建会替换上一个 ZIP。决定模组管理器是否把一次构建视为更新的是[模组 ID](wiki:build-and-install#mod-id)，而不是版本号。此设置适用于所有项目。
- **构建完成后在资源管理器中显示 ZIP** 会打开资源管理器并选中该 ZIP。

### 补丁文件 {#patch-files}

**同时将补丁文件保存到文件夹中**会把模组的补丁文件放在每个 ZIP 旁边，位于与 ZIP 同名的文件夹中。它们是 `.patch_0` 文件，以及模组有流式存储音频时的 `.patch_0.stream` 文件。可以用它们自己打包模组，例如用您自己的清单打包成 7z 压缩包。要安装它们，请为模组管理器打包，而不要复制到游戏文件夹中（[安装](#installing)）。此设置适用于当前项目。

只有当项目带有导入模组的纹理或模型时，构建才会有 `.patch_0.gpu_resources` 文件。音频不需要它。

### Wwise 响度分析 {#wwise-loudness-analysis}

**添加 Wwise 响度分析**会添加原版音频文件所带的响度数据。它不会带来可以听出的差别。它需要安装 Wwise，并会让构建变慢。此设置适用于当前项目。

### 包含这些声音的所有音频库 {#every-bank-with-the-sounds}

一个声音经常位于不止一个音频库中。多把武器共用的片段位于每把武器的音频库中，有些片段甚至位于上百个音频库中。默认情况下，构建只修补项目列表中的声音集、音乐和归档的音频库。这样模组会保持较小，与其他工具制作的模组一样。

**修补包含这些声音的所有音频库**会把新音频放入每个含有这些声音的音频库。这样，凡是用到这些声音的地方都会播放新音频，包括项目未列出的武器。模组会变大，有时会大出数百 MB。如果在应该播放新音频的地方仍然播放原版，请开启此项。此设置适用于当前项目。

有些声音无论如何都会放入每个音频库：

- 音乐。每个任务的音乐音频库都有每个阵营音乐的副本，`music_init` 也有其中大部分的副本。游戏使用最先加载的副本。带有旧时序的副本会以旧的时长播放新音频，导致音乐被截断或变成静音。
- 存放流式存储声音（例如语音台词）开头部分的音频库。每个这样的音频库都会获得新的开头，因此原版永远不会在新音频之前播放。
- 列表中没有任何音频库含有的声音。

带有导入模组的项目还会计入该模组修补过的音频库。在[工具 ▸ Repatch](app:tools/repatch) 上，同一个复选框适用于 Repatch 的模组。关闭时，音频只会放入该模组修补过的音频库。

### 其他音频库中添加的音频 {#added-audio-in-other-banks}

新变体、层以及设为**仅此声音**的新音频会放入每个含有该声音副本的音频库，包括项目未列出的音频库，因为游戏播放的是最先加载的副本。例如，AC-8“机炮”的声音在石油钻机和运输船的音频库中也有副本。为这些声音添加音频的项目也会修补这两个音频库，这会把这些音频库自身约 30 MB 的音频放入模组。

**添加的音频只放入项目的音频库**会把添加的音频只放入项目列表中的音频库，以及导入其中的模组的音频库。模组会变小，但只要游戏先加载了其他音频库中该声音的副本，就会播放原版。除非模组大小比那些地方的声音更重要，否则请保持关闭。列表中没有任何音频库含有的声音仍会放入每个含有它的音频库。此设置适用于当前项目，在开启**修补包含这些声音的所有音频库**时不起作用。

## 安装 {#installing}

构建结果是采用共享清单格式的 ZIP，Helldivers 2 的模组管理器可以导入它。

1. 在模组管理器中导入 ZIP。
2. 部署模组。
3. 启动游戏，前往会播放新音乐的地方。

> [!WARNING]
> 不要手动把补丁文件复制到游戏的 `data` 文件夹中。模组管理器在部署时会为所有模组的补丁编号。手动复制的补丁会被覆盖，或者会覆盖另一个模组。

## 两个模组更改同一个音频库 {#two-mods-that-change-the-same-bank}

模组包含它所更改音频库的完整副本。如果两个模组更改同一个音频库，它们的更改不会合并。后部署的模组会替换另一个模组中该音频库的副本。音乐模组共用大部分音频库，因此无论用什么工具制作，两个音乐模组都无法同时部署。[合并模组](wiki:combining-mods)可以把它们合成一个模组，包含两者的音频。

## 更新 {#updating}

在模组管理器中导入新的 ZIP。只要 ID 相同，它就会替换已安装的版本，而不会再添加一个副本。重新部署并重启游戏。

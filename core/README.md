# audiodiver (core)

A headless library and command-line tool that builds Helldivers 2 audio replacement mods from a `.audi` project into a verified mod manager ZIP. The editor (`../app`) runs it as a local API server.

```
pip install -e "core[loudness,test]"     # loudness = optional Wwise analysis
python -m audiodiver new my.audi --name "My Mod" --from-folder replacers
python -m audiodiver build my.audi       # -> build/<name>-<version>.zip (or the project's build_folder, or --out DIR)
python -m audiodiver inspect some.patch_0   # what a patch changes against the current game
python -m audiodiver index --rebuild
python -m audiodiver serve --port 8765 --token dev   # the editor's API (the desktop app starts this itself)
python -m pytest core                    # unit tests + golden builds of the three mods (needs the game)
python core/tools/import_sounds.py       # dev: the Index's sound data, from the community's workbook (see the file)
python core/tools/import_subtitles.py    # dev: each voice line's subtitle and the names of clips without words (S7)
python core/tools/import_exertions.py    # dev: the Helldivers' exertions by kind and voice, from a mod's notes (see the file)
python core/tools/import_logo.py         # dev: the default mod icon and the app icon's source, from assets/logo
python core/tools/import_bank_history.py OLD_INDEX BUILD   # dev, after a game update: what the banks lost and gained
python core/tools/i18n.py extract        # dev: the messages in tr(), ntr() and N_() into locale/<language>.po
python core/tools/i18n.py data           # dev: the texts the data files show into locale/data/en.json, for translators
python core/tools/game_names.py          # dev: the Index names the game writes in other languages (needs the game)
```

The build needs ffmpeg, wav2wem and vgmstream-cli (see `audiodiver/wem.py`). The core finds the game folder through Steam, using the registry to locate Steam. The editor's Settings ▸ System can choose another folder, and the core stores that choice in `%LOCALAPPDATA%\Audiodiver\settings.json` (`game_data`). If no folder is chosen, the `HD2_DATA` environment variable takes priority over Steam. The caches (the audio index, encoded WEMs, the Wwise scratch project and the mods Combine read), the log and the global notes (`notes.json`) are also in `%LOCALAPPDATA%\Audiodiver`, or wherever `AUDIODIVER_CACHE` names (a portable copy of the app sets it to its `data` folder). A release carries the core in an embeddable Python with the tools beside it (`app/scripts/release.py`). The core rebuilds the index when the game's files change.

| Module | Role |
|---|---|
| `game.py` | finds the game, reads packages from the slim bundles (vendored `_vendor/slim.py`, MIT; a bank or a table is read from only the chunks that hold it, `bundle_part`) and the voice packs next to them (DSAR files, one set per installed language), murmur64; the game's version (Steam's build ID), which a build notes in its project |
| `index.py` | which banks hold or play each sound, which archives hold each bank or stream, which language a voice bank is in, and the IDs of every bank's objects (an object is often copied into many banks); cached per game version |
| `bank.py`, `music.py` | Wwise v154 bank chunks, a node's settings (its prop bundle) and music objects (round-trip byte-identical) |
| `patch.py` | the surgical patch writer: copies vanilla banks and changes only the replaced audio, its sizes, its timing and its gain (a replacement without audio sets only the gain: Make-Up Gain on an original clip, `Project.gains`), plus exactly what a project adds and an imported mod's settings; `verify` enforces that. Every bank that holds a replaced clip gets the new audio, whether or not something in that bank plays it (footsteps keep their clips in banks of their own; the game plays the first copy loaded), and the start of a streamed clip kept in a bank holds the whole header and whole packets, as in every prefetch Wwise lays out (`wem.prefetch_size`; a header cut short crashed the game). The patch goes to disk a bank at a time (`PatchWriter`, a `.partial` renamed when whole) and is verified from the file, one bank at a time. A segment takes the project's cue points only where one of its tracks plays new audio, and an Entry at or after the Exit stops the build (`CueError`). A mod's files besides audio (text, models, textures: `Carried`, read by `carried_of`) go in byte for byte, with their `.stream` and `.gpu_resources` data and their entry's unnamed fields; `verify_carried` reads them back |
| `addition.py` | audio added to the game's: a new take in a random container, a layer that plays with a container (through its switch or layer parent, or a twin of each play action), a clip of its own for one Sound. Every copy of what it changes gets the same change, under new 30-bit IDs the game doesn't use; `check` verifies a patched bank against the plan. Reading a mod's patch (`from_patch`), the game's objects of an older version that the mod's bank copies still have aren't taken for the mod's: `data/bank_history.json` (`tools/import_bank_history.py`) lists what each bank lost and gained since earlier builds, and the fingerprints of objects the game changed since (`bank.fingerprint`, kept in the index). A copy that is another bank's (a tool that merges an object's copies across banks) isn't the mod's either (`merged`). The changes left out in each bank are counted by bank (`other`); `Session._patch_audio` says them with the bank's name. `cue_points` reads the cue points of the segments that play the new audio where they aren't where a build puts them, so Import, Repatch and Combine keep them |
| `wem.py`, `akd.py` | WAV→WEM encoding; a .wem given as audio, read through vgmstream wherever ffmpeg reads the other files (`decoded`, cached with the previews); every clip a build writes gives the codebook hash of its own setup, as Wwise writes it (`with_codebook_hash`; wav2wem writes one hash for every setup, and the game shares one decoded codebook among the clips playing at once that give the same hash); optional Wwise loudness/HDR analysis chunk |
| `project.py`, `build.py`, `cli.py` | the `.audi` format and what stops a build (`problem_list`: each problem with a kind, which the window goes by: the Project tab fixes `name`, `icon`, `icon_missing` and `mod_id`), the build pipeline (an imported mod's audio keeps its own encoding: `keep_encoding`; so does a .wem in the game's Vorbis, mono or stereo: `ready_wem`; a sound goes into the project's banks, an imported mod's or the list's, unless `every_bank`: `reach`; added audio and settings go into every copy, or with `project_banks_only` into the project's banks too: `own_banks`; music keeps every bank), the CLI (also the Tools as commands: `scan`, `repatch`, `combine`, `check`, each with `--json`, running the window's own jobs; Audiodiver Utils ships it as `audiodiver.cmd`; [command-line.md](command-line.md) documents it) |
| `projectfiles.py` | a project's folder: which files it uses, whether its folder is its own (`own_folder`), moving it into one (`carry`: renamed into place, copied where another project in the old folder uses a file, put back on a failure), its paths written again for a new place (`rebase`; `whole` when the folder moves with everything in it: Move project, `Session.move_project`), collecting files from outside into `audio/added`, the files nothing uses (to the Recycle Bin; a drive without one asks first), and packs: a ZIP of the project and its files (`.audipack`), without builds. Beside the project file, `slices` and `imported` can be a person's own folders, so only files named as Audiodiver named them count there (`LEGACY_FILES`) |
| `installed.py` | the installed mods (the mod managers' libraries, HD2 Arsenal's and Echelon's, and the game's `data/*.patch_N`) checked for sound banks of an older game version: older copies of actor-mixers other banks share (they can mute sounds far beyond the mod, like all gunfire), or banks an older version had; the libraries' entries as their files have them (`manager_entries`: Arsenal's data file, read as far as it goes, and Echelon's published `library.json`) |
| `repatch.py` | finding a mod's patches in a `.patch_N`, a folder or a ZIP, with what a mod manager's manifest says (name, icon, id, options; without one, the file's name less what a download added), a folder's patches as one part in load order, and packing the mod again as it was with new patches; `Session.repatch` rebuilds them on the current game, each in a temporary project, with the patch's other files carried as they were: only the new ZIP stays |
| `combine.py` | Combine Mods: a mod's options as mod managers offer them (each Option on or off, one SubOption of an Option that has them), the patches a choice deploys in the order they apply, the choice a mod manager's library records (`recorded_picks`: Arsenal's unpublished format as far as it goes, Echelon's `choices`/`selected`), and the clashes between mods (two mods' other audio for one clip, two clips of their own for one Sound, two values of one setting, which names the setting and the unit of the values: `prop_name`, `prop_unit`; an object that plays a clip in a clash follows its winner) with who wins (the later mod, unless chosen). `Session.combine_read` reads the mods into the cache (`combine/<digest>`, kept in memory too) and `Session.combine` makes a temporary project of what wins (every mod's takes and layers kept) and builds it into one ZIP in `Documents\Audiodiver\Combined`, with the mods' other files as they were (the later mod's, for one ID) |
| `arsenal.py` | the mod ZIP/manifest packager (the manifest format mod managers share; an empty `.stream` or `.gpu_resources` isn't packed), the patch files saved beside a ZIP (`save_patch_files`, the project's `patch_files`), and the icon: an image, or the default one (Audiodiver's logo, `data/icon.png`), with a border and rounded corners |
| `cuemap.py` | every piece of music the game can play, walked from the music root switches and events; cached per game version |
| `catalog.py`, `data/` | names for people: every music cue in the game's own structure, cue and slot names, locks. `data/catalog.json` is hand-curated; `names.json` (cracked Wwise names) and `labels.json` come from dictionary attacks on the Wwise names and the music workbook (`tools/import_knowledge.py`); `notes.json` (hand-kept) names and explains single clips, with warnings and minimum lengths; `exertions.json` (`tools/import_exertions.py`) does so for the Helldivers' exertions, by kind and voice, and a bank whose sounds the notes all name lists them by name. Shown texts follow the app's writing rules in `app/README.md`. They name no people or sources (those are in the app's Credits) and give no testing status. The data stays in English for searches and comparisons; what goes out is translated (`label_shown`, `clip_label`, `clip_notes`), and the All cues tree is ordered by the English path |
| `musiclist.py`, `data/music.json` | the music as the Index lists it: sections in mission order, items a player would recognise (one per faction role for combat: arrival, exploring, battle...), transitions named by what they connect, and which transitions or stingers sit next to which music. Names made of pieces ("Battle or Exploring", "Over …", "Terminid Battle") are whole messages with fields; the rules compare a place's kind and English names, and order the combat parts by a key (intensity, then the rest of the biomes), so a translation changes no order. A name in another language comes with the English (`en`) |
| `library.py`, `data/sounds.json`, `banks.json`, `voices.json`, `subtitles.json` | the Library: the Index (the music, then the sound sets the community has named, by category; Weapons by loadout slot, from `WEAPONS` in `tools/import_sounds.py`, and an ID a set had before a rename or a move still finds it) and All Archives (every archive with audio in it). A bank opens as its sounds, grouped by take and labelled with what a voice line says: its subtitle (`subtitles.json`: which one, and whether the ID is certain or one of several with the same words), else the community's transcript, else the call another voice built the same way makes in its place. Clips without words are named by what they are ("Grunt 3", per bank) and a voice bank lists the ones it holds for other banks by kind. By container ID (`ids`), the sounds of a bank are listed as Wwise tools list the bank tree: a group per container right above the Sounds, named by the container ID, in depth-first order, with the containers above it. A row gives the Make-Up Gain the game gives the Sound (`game_gain`), which a slot gain adds to. `subtitle_lines` goes back from subtitles to the voice lines that say them, in one language's voices. `sounds.json`, `banks.json` and `voices.json` are written by `tools/import_sounds.py`, `subtitles.json` by `tools/import_subtitles.py` from the S7 spike's matches. The window goes by codes, not by the names the Library makes up: each group of a bank has a `kind` (sound, layer, run, wordless, other, absent, streams) and `made_up` when the name is only a number ("Sound 6"); an archive called by its ID has `id_name`. An Index name in another language comes with the English (`en`), which the Library's search finds too |
| `titles.py` | title case for every name the Library shows, in English: a data name is title cased, then translated (`named`), and a name made of pieces is title cased as a whole in English and left as written in another language (`shown`) |
| `i18n.py`, `locale/` | the language of what the core shows: messages through `tr()`, `ntr()` and `N_()`, from `locale/<language>.po` (`tools/i18n.py extract`, `missing`, `fill`); the texts of the data files through `dtr()`, from `locale/data/<language>.json`, keyed by the English as shown. `locale/data/en.json` lists every data text with where it comes from (`tools/i18n.py data`, `data-missing`, `data-fill`); the Index names the game itself writes come from the game's text (`tools/game_names.py`: a name that is a whole line of the game's US English text, with the designation put back as the language writes it). The window sets the language (`Session.set_language`); with another language the catalog, the library and the caches made from them are made again in the background while `stage` shows a loading step |
| `strings.py` | the game's text: string tables (one per table and language, in archive 9ba626afa44a3aa3), read, searched and written back whole with a project's lines in them |
| `audio.py` | waveform peaks (numpy when installed; 0 to 255, or 0 to 32767 for a waveform zoomed in on quiet audio), sample-exact slicing of one song into pieces, and the built-in silence a replacement can play instead of a file |
| `render.py` | renders segments and whole cues the way the game plays them (exports, Play through), and copies a file into another format at a Make-Up Gain (`transcode`); needs numpy. The Export panel's choices are `Session.export_list`: entries, each a cue with some or all of its slots, what to write (each slot, each segment, the whole cue, or one fight as the game plays it) and which audio (the Original, the audio as the mod plays it, both), named in full, short or by source ID, in a folder each or not; WEM files of the Original are the game's own bytes. `export_preview` gives the names before anything is written, and `export` is the same for one cue |
| `tutorial.py` | the audio the in-app tutorials put in slots, made rather than shipped (a laser shot and its echo for the Liberator tutorial), the same every time; `Session.tutorial_audio` writes it into the open project's folder |
| `loudness.py` | how loud a file sounds (ITU-R BS.1770 in numpy: K-weighted, 400 ms blocks), for Match the original loudness (`Session.match_loudness`): a sound under 3 s by its loudest block, longer audio by its gated integrated loudness, a clip shorter than a block by its own length; cached per file |
| `soundtrack.py` | the Soundtrack: how each piece of music plays (`Piece`: original without some items, one song cut into segments (`song`, with the file it was cut from) or a playlist of whole songs (`tracks`, shuffled or not, from the first song at each start or going on, `resume`) in an order of their own, silent, or the same as another piece; a level). The editor fills a playlist place by place (`playlist_set`) and copies a piece's setup to others (`soundtrack_copy`). `plan` turns the project's pieces into new playlist trees, jump rules that start over where an item is gone, switch paths led elsewhere, and rules that leave a whole track at the next bar; `apply` puts that on every copy in a bank, and `fight` plays one fight as the game does (step groups go on where they stopped, the music starts on its openings) |
| `editor.py`, `server.py` | the editor session (autosave with each change or on a timer, the edits waiting in memory until a save or `flush`: a build, a move, closing; save on demand; undo/redo, and `history_go` for the History list, which moves several edits at once with one restore and one save, the project's list of what it works on, album fill, slicing into chosen slots, patch import, repatching, combining mods, background builds) and its token-protected localhost API. The Combine entries are `combine_scan`, `combine_installed`, `combine_folder`, `combine_read` and `combine`; the window plays a clash's versions with `/audio/file?path=` and its Original with `/audio/vanilla/<source>`. Home shows the last project's icon from `/projects/icon?path=` (`project_icon`, a .audi file only). Import Mod's entries are `mod_scan`, `mod_preview` (the patches a choice of options deploys and the lines of the game text the mod changes, read without decoding audio) and `import_mod` (a job: into a new project, opened once made, or into the open one as one edit; `import_patch` brings a patch's lines of text the same way); the window shows the mod's icon from `/mods/icon?path=` (`mod_icon`, only the image the mod's manifest names). `project_state` keeps what it finds out about the project's folder until the folder or the files the project uses change (`_folder_facts`), and gives each problem's kind beside it (`problem_kinds`). `set_language` with another language names everything again in the background (`_rename`; `stage` is a loading step until it is done); the same language again changes nothing |
| `notes.py` | the keys a project's notes go by (`Project.notes`, written in the details panel: a slot's clip, an Index item) and their checks. A note whose thing a game update took away stays in the file |
| `updates.py` | Audiodiver's own releases on its GitHub repository, for the app's Updates tab (the `releases` method; it only reads, the shell installs). `AUDIODIVER_RELEASES` names a file in the GitHub API's format to read instead (development, tests) |
